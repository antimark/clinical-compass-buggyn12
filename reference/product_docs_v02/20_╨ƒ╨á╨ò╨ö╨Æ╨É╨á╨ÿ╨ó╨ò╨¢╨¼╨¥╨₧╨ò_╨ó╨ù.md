# 20. Проект технического задания v0.1 — для обсуждения

**Статус:** черновик, не принят командой. **Цель:** дать разработчикам контракты экранов/сценариев, не выдавая идеи за завершённые задачи.

## Вертикальный демо-сценарий

1. Администратор создаёт клинику, назначает врача с местом лицензии, приглашает синтетического пациента.
2. Пациент принимает приглашение, видит предоставляемые разрешения и выполняет check-in/валидированный опрос.
3. Состояние и оценка доступны только связанному врачу, с проверенными ACL.
4. Врач просматривает timeline, назначает следующий опросник и подтверждает/отклоняет подсказку маршрутизации.
5. Пациент отмечает приём назначенного препарата и возможный НЯ; врач видит отдельные записи.
6. На синтетическом риск-событии система создаёт критический алерт, записывает доставку и acknowledgement; в демонстрационном клиническом сценарии — проверяет «Авиандр» по актуальному источнику.
7. Исследователь видит только отдельный синтетический снимок с предварительными агрегатами и фильтрами.

## Минимальная структура DTO / серверный доступ

Всякая клиническая запись: `id, patient_id, source_type, observed_at, recorded_at, author_id, org_id, status, version, provenance`. Для недоступного поля API **не возвращает значение**: безопасный отдельный `field_capabilities` содержит допустимые действия, но не sensitive inference.

## Demo acceptance / Definition of Done

Один синтетический end-to-end запуск проходит без ручного прямого изменения БД; присутствуют negative ACL tests; все предложения лечения/маршрутизации требуют подтверждения врачом; screenshot состояния недостаточен для зачёта alert, требуется событие доставки/ошибки.

## Не включать в хакатонный обязательный объём без отдельного решения

Аудиозапись реальных консультаций; запуск AI-терапевта с открытым доступом к реальным пациентам; автоматическое определение риска по видео/мимике; исследовательский просмотр сырых медкарт; автономное назначение лекарств.

## Требует финализации

Пороговые значения клинических правил и валидированная шкала; разрешения полей для каждого типа врача; SLA критического алерта и адресаты; API auth и CSRF; семантика ретроспективного adherence; выбор MIS-интеграции и целевой стек UI.
