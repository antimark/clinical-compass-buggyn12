# Словарь проекта

| Термин | Значение в Clinical Compass |
|---|---|
| **Core DB** | Общая закрытая БД платформы, где находятся клинические данные, профили и связи. |
| **Stats DB** | Отдельный SQLite-файл с утверждённым исследовательским набором, не доступ к core. |
| **RBAC** | Права по роли (`DOCTOR`, `PATIENT` и т.д.). |
| **ABAC** | Права по атрибутам контекста: клиника, пациент, активная связь, цель, время. |
| **Field-level ACL** | Разрешение на операцию с **конкретным** полем пациента. |
| **Grant / Deny** | Явное предоставление / запрет права. Deny и hard switch имеют приоритет. |
| **Access template** | Версионируемый конфигурируемый набор обязательных/дополнительных полевых прав для конкретной связи. |
| **Consent** | Зафиксированное разрешение/основание для определённой обработки, не синоним ACL. |
| **Organization membership** | Участие пользователя в конкретной клинике в определённой роли. |
| **Doctor–patient link** | Отношение наблюдения, включая клинику и действующий шаблон прав. |
| **Invitation** | Ограниченный токен, который создаёт отношение между профилями после принятия. |
| **License seat** | Договорное активное место врача в организации. Число мест настраивается. |
| **Clinical provenance** | Кто, где, когда и на каком основании создал медицинскую запись. |
| **Dynamic field registry** | Справочник новых полей, типов, валидации, версий и чувствительности. |
| **Clinical alert** | Сигнал потенциального риска, требующий проверки и реакции уполномоченного лица. |
| **Clinical decision** | Зафиксированное медицинское действие/решение с подтверждением врача. |
| **Outbox pattern** | Сохранение события для надёжной асинхронной отправки после транзакции. |
| **PII / ПДн** | Данные, способные идентифицировать человека; контекст и сочетание полей имеют значение. |
| **De-identification** | Общий термин для методов снижения идентифицируемости, не равнозначен анонимизации. |
| **Псевдонимизация** | Замена идентификаторов при потенциально обратимой связи через отдельно защищённый mapping. |
| **Анонимизация** | Обработка с оценкой риска повторной идентификации; удаление ФИО недостаточно. |
| **Encryption** | Обратимое шифрование с ключом. |
| **Hash** | Необратимое преобразование; не средство восстановления исходного значения. |
| **Feature flag / kill switch** | Серверное правило быстрого отключения функции, имеющее приоритет над старыми правами. |
| **RPO / RTO** | Допустимая потеря данных в результате сбоя / целевое время восстановления. |
| **MVP** | Минимальная работающая реализация; инфраструктура для функции ≠ полное выполнение клинической функции. |
| **B2B2C** | Продажа/внедрение через организацию с предоставлением интерфейса пациенту. |
| **Фармаконадзор** | Процессы выявления и сопровождения сигналов безопасности лекарств, не доказательство причинной связи по одному сообщению. |
