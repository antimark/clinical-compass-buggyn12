# Clinical Compass — пакет документации для команды

**Версия документации:** 0.1 (рабочая спецификация, 17.10.2026).  
**Статус:** проектирование; наличие описанной функции не означает, что она уже реализована в коде.

## Назначение

Это переносимый набор Markdown-документов для продуктовой, клинической, дизайн- и backend-команд, а также для передачи контекста в новый чат. Все файлы читаются по отдельности. Начать рекомендуется с `01_КЕЙС.md`, `02_КОНЦЕПЦИЯ.md`, `03_БЭКЕНД_АРХИТЕКТУРА.md` и `06_ЮЗКЕЙСЫ.md`.

## Как трактовать утверждения

- **[КЕЙС]** — прямо содержится в оригинальном PDF задания, приложенном в `sources/`.
- **[КОНЦЕПЦИЯ]** — отражает первоначальный авторский документ в `sources/`; зачастую сформулировано как гипотеза, а не доказанный факт.
- **[СОГЛАСОВАНО]** — принято пользователем в ходе обсуждения архитектуры в текущем проекте.
- **[ПРОЕКТНОЕ ПРЕДЛОЖЕНИЕ]** — рекомендуемая реализация, требующая утверждения до production-разработки.
- **[ОТКРЫТО]** — решение или измеряемый показатель ещё не зафиксированы.

Источники лежат в `sources/`, рядом с `docs/`. Этот набор **не является юридическим заключением, утверждённым клиническим протоколом или доказательством соответствия законодательству**.

## Быстрый порядок работы

1. Продукт и клиническая команда утверждают `01`, `02` и сценарии `06`.
2. Backend-команда фиксирует открытые решения `12`, затем использует `03`–`05` и `07`.
3. Ответственные за безопасность/обработку данных проверяют `04` и `08`.
4. QA составляет тесты по `10` и матрице `11`.
5. Для нового чата прикладывают необходимую часть пакета и `13`; **не пересылают рабочую БД, секреты и реальные данные пациентов**.

## Важное разграничение

Задание хакатона требует работающего клинического ассистента, включая оповещения, актуальную справочную информацию и сценарии с препаратом «Авиандр». Текущий этап разработки *бэкенд-каркаса* может предоставлять инфраструктуру для этих модулей, но не заменяет их фактическую реализацию к финальной демонстрации кейса.
