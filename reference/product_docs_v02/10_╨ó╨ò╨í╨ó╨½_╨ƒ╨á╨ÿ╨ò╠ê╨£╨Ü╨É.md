## Приёмка функциональных требований хакатона (к финальной демонстрации)

| Направление | Проверка |
|---|---|
| Шкалы | Реальная валидированная русская версия, источник, сохранённая версия, расчёт и доступ |
| Справка по терапии | Действующий источник, препарат и допустимый инструкцией контекст, ссылки |
| Риски / adverse events | Обнаружение, запись, сигнал врачу, подтверждение и корректный статус |
| Динамика | Два и более наблюдения, временной ряд и график в интерфейсе |
| Пациентский UI | Самоотчёт сохраняется и виден разрешённому врачу |
| Коммуникация | Сообщение проходит от одной стороны к другой по проверенной связи |
| Приверженность | Фактические записи соблюдения режима, расчёт и отображение |
| Маршрутизация | Сигналы «обязательно»/«желательно», решение подтверждает врач |
| Авиандр | Клинический сценарий с профилем, рассмотрением терапии и маршрутизацией |
| Алертинг | Критическое событие создаёт alert и происходит фактическая попытка/подтверждение доставки |

## Нефункциональные проверки

- **Performance:** определить с командой измеримые целевые p50/p95 API и время alert; официальных числовых нормативов в кейсе нет.
- **Load:** измерить количество конкурентных пользователей, время отклика, долю 5xx и `database is locked`; провести особое испытание конкурирующих WRITE.
- **Restore:** создать валидный backup и восстановить на чистом окружении; проверить foreign keys, количество записей, grants, outbox.
- **Failure:** прервать процесс после COMMIT clinical event, до доставки alert; после восстановления событие должно остаться и быть отправлено без дубля клинического решения.
- **Cross-platform:** проверить целевые браузеры и устройства (уточнить матрицу).
- **Flexible schema:** добавить новый field, scale, medication reference и правило без изменения permission core.
- **Input extraction:** тестировать на синтетических/разрешённых документах разных форматов, отдельно измерять извлечение диагнозов, назначений и других полей.

## Синтетический набор (seed)

Минимум: 2 организации; 2 врача (один работает в обеих); 3 пациента (у одного два врача); Clinic Admin с двумя схемами; Platform Admin; 2 researchers и 2 datasets с разными grants; 2 версии шаблона; 5 динамических полей разных типов; 1 критический сигнал; 1 отзыв согласия; 1 история переприкрепления.
