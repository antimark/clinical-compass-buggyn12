# 25. UX-спецификация и wireframes v0.2

**Демонстрируемый интерактивный макет:** `../mockups/clinical_compass_prototype.html`. Это автономный HTML/CSS/JS без Flask/SQLAlchemy/API; в нём **нет** реальной проверки прав, сохранения в SQLite и клинической обработки. Тексты/пациенты/события вымышлены и предназначены для обсуждения.

## 1. Навигация врача — «что требует внимания?»

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ Clinical Compass (DEMO / SYNTHETIC)   Клиника ∨   Специальность ∨   Профиль│
├─────────────────────────────────────────────────────────────────────────────┤
│ Сайдбар: Пациенты / Запросы на приём / Алерты / Сообщения / Расписание     │
│                                                                             │
│ [Критические сигналы (2)] [Новые запросы на приём (3)] [Назначенные формы] │
│ ─────────────────────────────────────────────────────────────────────────── │
│ Пациенты  [Поиск...] [Приоритет ∨] [Фильтр ∨] [Вид колонок]                │
│                                                                             │
│ Внимание   Пациент       Динамика     Данные/источник      След. действие   │
│ Срочно     Синт. А        ухудшение   послед. ввод 14:10   Оценить сигнал  │
│ Повыш.     Синт. Б        без перем.  нет отчета 7 дней   Запросить форму  │
│ Планово    Синт. В        улучшение   послед. ввод вчера  Плановый визит   │
└─────────────────────────────────────────────────────────────────────────────┘
```

**UX состояния:** критические алерты отображаются **над** таблицей и имеют названия действий; второй отдельный сценарий — запросы записи, не перемешиваются с критическими сигналами. Приоритет явно объясним, невозможна сортировка по скрытому полю. При `not_recorded` «нет данных» — не диагноз «стабильно».

## 2. Карточка пациента

```text
Синтетический пациент А  [Контакты*] [Назначить форму] [Создать запись визита]
* Контакты и все разделы только по разрешениям
╔═══════════════╗ ╔══════════════╗ ╔══════════════╗ ╔═══════════════════╗
║ Динамика      ║ ║ След. визит  ║ ║ Новые сигналы ║ ║ Назнач. задания   ║
╚═══════════════╝ ╚══════════════╝ ╚══════════════╝ ╚═══════════════════╝
[Обзор] [Динамика] [Анамнез] [Лекарства*] [Психотерапия*] [Визиты]
[Другие специалисты*] [Чат*] [Клинические решения]

Граф симптомов / валидированной шкалы + вертикальные маркеры изменения дозы
Timeline: 10.10 check-in | 12.10 посещение | 15.10 изменение дозы | 17.10...
Направление / решение: [обязательно|желательно] → [Оценить] → [Подтвердить]
AI summary (черновик): [Исходники] [Редактировать] [Подтвердить врачу]
```

`*` пункт скрывается целиком, если запрещён доступ; UI может отдельно показывать «доступно по запросу» лишь когда это не выдаёт чувствительный факт. В карточке психотерапевта на месте `Лекарства` может быть `Поведенческая терапия`; конфигурация никак не меняет права сама по себе.

## 3. Экран пациента

```text
Сегодня | личное самочувствие (без принуждения к заполнению)
[Как вы чувствуете себя?  1  2  3  4  5 ]
[По сравнению с прошлым разом: лучше | так же | хуже | не знаю ]
[Добавить заметку (необязательно)] [Отправить] [Пропустить]

[Врач просил заполнить шкалу до приёма] → [Открыть]
[Следующий визит: 23 октября] → [Посмотреть / запросить изменение]
[Моё лечение] [Динамика] [Сообщение врачу] [Разрешения]

[Поддерживающий AI-чат: demo] → разговор → [Подготовить сводку]
                                            → [Просмотреть] → [Отправить врачу]
```

Контраст состояний: простой check-in для редкого пользователя, расширенные задания по желанию; пациент всегда видит текущую утверждённую терапию и собственную историю. Нельзя использовать streak/guilt как основной мотиватор.

## 4. Экран исследователя

```text
Dataset: SYNTHETIC 2026 v1            Поля: препарат, дозировка, неделя, ...
Фильтры: [Препарат ∨] [Доза ∨] [Длительность ∨] [Сценарий ∨]
Когорта: N 84       Полных наблюдений: 69       Пропущено: 15
Граф изменения самооценки по неделям    Частота отдельных симптомов
Сигналы: «повышенная частота жалобы» — exploratory; не причинность
[Экспортировать агрегированный CSV]
```

Фильтрация должна физически пересчитывать dataset, числа и график, а не показывать заранее нарисованный неизменный результат; разрешённые synthetic cases могут открываться отдельной карточкой.

## 5. Экран клиники — упрощённый

Очередь запросов визита, список сотрудников, приглашения, лицензии, уведомления технических ошибок. Никакой автоматической видимости историй болезней.

## 7. Сценарии пользовательской приёмки

1. Психиатр видит разрешённые назначения в карточке → психотерапевт того же пациента не получает медикацию даже в JSON, AI summary и экспорте.
2. Пациент нажимает mood 2/5 и «хуже», сохраняет → врач видит свежую точку и дату без перезагрузки seed.
3. Пациент описывает примерно два пропуска за 7 дней → UI показывает диапазон/приблизительность, а не две выдуманные даты.
4. Врач отправляет форму к визиту → пациент получает запрос и отвечает → ответ попадает в карточку.
5. Критический синтетический триггер → алерт сверху, врач нажимает acknowledge, статус сохраняется; отсутствие дежурства честно отражено в UI.
6. Пациент использует чат-бот → формирует черновик → отдельно подтверждает передачу; врач видит только разрешённое.
7. Исследователь сменил фильтр препарата → числа/графики изменились; персональные данные никогда не показываются.
