### Новые реализованные сценарии

1. Пациент → `/#/patient/tasks` → выбрать одну из четырёх пилотных форм → `POST /questionnaires/self-assign` → ответить на каждый вопрос → сохранить черновик → `POST /submit` → отдельная страница результата с исходными ответами и суммой баллов. После перезагрузки результат доступен в истории. Дополнительно опросник можно назначить врачом, имеющим разрешённую связь с пациентом.
2. Врач → `/#/doctor/questionnaires` → назначить опросник доступному пациенту → после его завершения открыть результат в модальном окне. В этом сценарии сервер остаётся арбитром доступа.
3. Справочник → выбор категории/поиск/страница → детальная карточка → доступные исходные поля, источники и кликабельные `https://` URL → перекрёстная карточка диагноза, лекарства, терапии или опросника. Используется серверная пагинация (50 элементов на страницу).
4. Evaluation Sandbox на чистой базе теперь отдельно создаёт определения четырёх пилотных и двух технических опросников **без** автоматического создания аккаунтов или историй пациентов.

### Клинические ограничения

Каталожные версии PHQ/GAD имеют `clinical_release_approved=false`, а медицинская, локализационная и юридическая проверки не завершены. Новый маршрут прохождения доступен только в `synthetic_dev` и явно подтверждённом `evaluation_sandbox`, только авторизованному тестовому пациенту. Он не меняет `clinical_gate=view_only` публичных карточек, не заявляет клиническую валидацию, не показывает диагноз/пороговые клинические заключения. Разрешение на использование конкретных русскоязычных редакций и правила обработки суицидальных ответов надо утвердить до использования на реальных людях. **Нельзя вводить данные реальных пациентов в оценочную сборку.**

Лекарственные карточки — информационные снимки и МНН, не гарантируют актуальную регистрацию, показания или пригодность схемы для пациента. Для назначения требуется сверка с действующей официальной инструкцией и решением врача. URL первоисточников представлены как ссылки, но доступность внешних ресурсов не проверялась онлайн.

### Где пользователь увидит заглушку, ограничение или не сможет завершить сценарий

**Не подключено (15 маршрутов):**

- `/register/specialist` — открывается пояснение, самостоятельного подтверждения врача нет;
- `/patient/messages/:threadId` и `/doctor/messages/:threadId` — не подключён неопознанный личный thread ID;
- `/patient/assistant` и `/patient/assistant/share/:draftId` — новый чат Qwen и отправка черновика пациентом не интегрированы с ACL;
- `/patient/appointments/:appointmentId/visit`, `/doctor/appointments/:appointmentId/visit` — видео/аудиоприём не реализован;
- `/patient/reviews/new/:appointmentId` и `/doctor/reviews` — написание/просмотр верифицированных отзывов не подключены;
- `/doctor/patients/:patientId/psychotherapy` — редактирование плана психотерапии отсутствует;
- `/doctor/import` — импорт выписки не подключён;
- `/research/cases/:caseId` — открытие отдельного исследовательского кейса не подтверждено;
- `/doctor/clinical-copilot` — нет безопасной интерфейсной привязки к разрешённому контексту;
- `/demo/journeys` и `/demo/profile` — отдельные сценарии оценки не подключены.

**Частично реализовано (16 маршрутов):** мастер онбординга, отзывы в каталоге врачей, создание заявки на приём, управление доступом пациента, часть врачебных планов/нежелательных событий/подтверждения сигналов, старый справочный article ID, приглашения и лицензии клиники, организационный аудит, конструктор когорт/сравнение/сигналы/экспорт исследователя и просмотр разрешений команды.

**Кнопки, ведущие к неготовым страницам:** меню врача «Помощник» (`/doctor/clinical-copilot`); переход к отдельному AI-чату пациента; ссылки на видеосеанс, отзывы, импорт, психотерапевтический план; некоторые исследовательские разделы. Такие переходы оставлены честными заглушками без ложного уведомления об успехе. Они не равнозначны отсутствующей странице: маршрут существует, но действие не работает.

**Справочник:** все 242 *внутренние карточки* могут быть получены по ID; внутренние связи проверены. Сеть/официальные внешние источники, динамические GET для каждого пользователя и связка с живым Flask остаются без сквозной проверки.

## Ограничения выполненного тестирования

- Текущая среда не содержит установленного Flask; попытка установки зависимостей оказалась заблокирована отсутствием сети. Поэтому запросы к реальной базе через Flask, CSRF и ACL, одновременная запись черновиков и интеграционное тестирование кабинета врача/пациента **не подтверждены**.
- Chromium доступен, но переход на локальный HTTP в этом окружении возвращает `ERR_BLOCKED_BY_ADMINISTRATOR`; автоматический browser E2E не завершён. `tests/browser_mock_acceptance.py` оставлен для исполнения на машине с разрешённым loopback и Playwright/Chromium.
- У прежнего набора frontend E2E-тестов имеются селекторы старого интерфейса; новая дизайн-система требует их адаптации.

Не используйте учётные записи или сведения реальных пациентов.
