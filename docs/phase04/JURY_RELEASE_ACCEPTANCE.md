# Clinical Compass — критерии готовности к показу жюри

**Статус на момент подготовки задания:** требования к выпуску, **не свидетельство прохождения тестов**. Реальный выпуск должен быть подтверждён отчётами Codex Phase 0–3 на Mac и в Docker. Все данные для проверки — синтетические. Медицинская валидация прототипа не утверждается.

## Что считается результатом

- Из исходников воспроизводимо запускается весь продукт: новый UI + Flask API + сохранение данных + клинический справочник + локальная модель Qwen через Ollama.
- Доступны связанные, действительно выполняемые пользовательские сценарии гостя, пациента, врача, исследователя и администратора клиники.
- Там, где алгоритм ещё исследуется, показано его **реальное экспериментальное поведение** с основаниями, врачебным контролем и маркировкой статуса; отдельный интерактивный пример явно обозначен как пример, не выдан за результаты Qwen.
- Проект можно передать жюри: команды установки/запуска, демоданные, сценарий показа, измерения, отчёты о тестах, Docker (после отдельной проверки). Без внешнего доступа к реальным пациентам.

## Основные gate-тесты

| № | Проверка | Необходимое доказательство / критерий |
|---|---|---|
| G01 | Окружение | Живой Flask + новая сборка UI, база и миграции; точные команды запуска в `cc-m1`, health OK, реальная авторизация/CSRF |
| G02 | Гость и четыре пилотных шкалы | PHQ-9, PHQ-2, GAD-7, GAD-2: все вопросы и варианты 0–3, граничные баллы 0–27/0–6/0–21/0–6, корректные ошибки, временный результат |
| G03 | Сохранение после входа | Гость → вход → собственный сохранённый результат; показ истории после перезагрузки и нового входа; не объявлять сохранённым до подтверждения сервера |
| G04 | Сохранение после регистрации | Гость → регистрация → перенос ответов и сохранённая история; другой аккаунт не получает результат |
| G05 | Врач и опросники | Назначение пациенту с разрешением, прохождение, просмотр ответов/суммы с проверкой ACL; без связи доступ закрыт |
| G06 | Clinical Intelligence и Qwen | Живой запрос к локальной `qwen3:4b-instruct`, предложения тегов и дословные evidence, редактируемый проект медкарты, врачебное подтверждение, маршрутизация, объяснения, ссылки на каталог; отдельно иллюстративное превью |
| G07 | Каталог целиком | Доступны 242 записи: 77 лекарственных карточек, 77 диагнозов, 58 методов, 30 инструментов. Проверены **все непустые разрешённые исходные поля** по каждой из 77 карточек, в том числе вложенные, источники и связки; работающая пагинация |
| G08 | Исследователь | Демонстрируемый сценарий от синтетического набора данных до фильтра/группы, метрики/методики и результата; если экспорт заявлен активным, он отдаёт корректный файл |

| G10 | Навигация | Инвентаризация всех реальных маршрутов (исходно 102), кликабельных действий и динамических состояний, без критических dead ends, 404/422/500 в основных сценариях; адекватные пустые/ошибочные состояния |
| G11 | Права и безопасность | Роли/организации, CSRF, consent, врачебное подтверждение, приватность дневника, отсутствие секретов/реальных данных в отчётах, логах и ZIP |
| G12 | Техиспытания | Сырые замеры response time p50/p95/при достаточном n p99, scripted Time on Task, ошибки, ресурсы, одна реальная LLM-генерация, безопасная малая локальная нагрузка 1/3/5 пользователей; указаны n и условия |
| G13 | Демонстрационный прогон | Два полных повторяемых запуска сценария жюри в чистой и перезапущенной среде, 10–15 минут, ссылки/скриншоты/трейсы, способ восстановления |
| G14 | Docker | Реальная сборка, `compose up`, миграции, volume persistence, health, 4 роли + гость, **реально доступный Ollama/Qwen**, 77 препаратов, проверки повторного запуска и отсутствие публичных портов/секретов |

## Статусы и критические приоритеты

- `PASS`: успешный реальный тест с понятным сценарием, HTTP/DB подтверждением и приложенным доказательством.
- `ILLUSTRATIVE`: отдельно обозначенная, воспроизводимая демонстрация интерфейса, не считается `PASS` для AI/API/сохранения.
- `PARTIAL`: часть взаимодействий работает, но сценарий до результата не завершён.
- `FAIL`: воспроизводимый сбой; `BLOCKED/NOT_RUN`: объективно не проверено, указана причина.
- `P0`: утечка данных/обход ACL, невозможность старта, потеря результатов опросников, невозможность показать основные 4 роли или полный каталог, ложное утверждение об AI-сохранении/медицинской оценке. `P1`: сломанная ключевая кнопка/сценарий, устойчивые 422/500, потеря контекста, отсутствие рабочего пути возврата. `P2`: некритичная полировка.

## Лимит использования Codex и сохранение результатов работы

Работа проводится по [протоколу субагентов](SUBAGENT_BUDGET_PROTOCOL.md): один основной агент, не более двух параллельных специалистов, не более четырёх делегирований без дополнительного разрешения. Перед каждым дорогостоящим прогоном переиспользовать уже подготовленные тесты, а после фазы создавать `.agent/EXECPLAN_ACTIVE.md` и `.agent/CHECKPOINT.md`. Достижение пользовательского лимита не считается выполнением этапа: незапущенные испытания помечаются `NOT_RUN/BLOCKED`, а накопленные исходники, команды и фактические результаты остаются в репозитории для продолжения.
