# Clinical Compass: UX/API repair for evaluator demo (2026-10-26)

This update modifies source code, not screenshots. It is intended for a **local, explicitly synthetic development demo**, or for the existing isolated evaluation workspace described in README. Never load identifiable real-patient health records. Do not use for care delivery or claim validation as a clinical medical device.

## What changed

- Startup: `scripts/start_windows.cmd` and `scripts/start.sh` enable the six existing gated Clinical Intelligence/chat/review/referral/safety capabilities **only when `CC_APP_ENV=synthetic_dev`** and only if a flag has not explicitly been set. The guarded `evaluation_sandbox` startup already enables these features. There is no role, consent, CSRF, or publication bypass. In order to use the local Qwen path, a compatible Ollama server and specified model must already be running.
- Patient chat: an explicit disabled-module explanation instead of an opaque resource-not-found error. Access to private sources requires the same authenticated patient session as before.
- Safety panel: clearer recovery text when the clinician's safety endpoint cannot be read. The server distinguishes detection, test-inbox delivery, physician view and acknowledgment, and enforces audit.
- Encounter draft: client-side checks for required narrative and empty plan item titles; backend returns Russian 422 messages in the standard JSON shape. Medication references are removed when the user reclassifies a plan item as non-medication. Add/remove no longer resets scroll to the top on the long editor page.
- Two clinical-library views: `#/clinical-library` is the unified v5 catalog, and `#/doctor/clinical-library` defaults to the same catalog. The legacy full instruction reader remains explicitly at `#/doctor/clinical-library?view=legacy`, with its 8 archived source instructions and clinician-facing workflow. Medical-review packet route `?view=review` is unchanged. v5 detail pages show extra source-backed information for diagnoses, therapies and medicines, and retain reciprocal links.
- The included library contains **77 diagnoses, 77 medicine entries (69 INN cards plus 8 source-product snapshots), 58 methods and 30 instrument metadata entries**. In the unified directory all are searchable, paginated and crosslinked as supported by included data. This count describes entries, *not* approvals for patient use or current drug registration.
- The two **technical questionnaires** (10- and 15-item examples) remain the executable assignment/patient-completion flow. The 30 v5 instrument metadata entries do **not** establish Russian validation, digital reproduction rights or permission to display full questions. Those are not silently unlocked. Use explicit rights/validation review before adding instrument items and interpretations.
- The three pre-existing fixture physicians now have a stage-appropriate fictional years-of-experience/education/certificate projection in the public directory, explicitly labeled as demonstration; all actual credentials and claims remain subject to verification. A single prominent topbar label states the synthetic demo condition; technical provenance/safety disclaimers remain where legally and medically material.
- Spacing, mobile wrapping and dark-theme input borders were adjusted without changing the platform's common tokens.

## How to try on Windows

1. Stop the earlier server; extract this ZIP **to a new source folder**. Keep your private workspace/database separate and do not overwrite it without a backup.
2. Open this folder in VS Code. Set `CC_CONDA_ENV` to the name of the **existing** Conda environment if it is not `clinical-compass`, then run `scripts\\start_windows.cmd` from a terminal in the project folder. Use the displayed port (default **8000**). If running `backend/run.py` through a custom VS Code configuration, that configuration must explicitly set the same `CC_DEMO_MODE=1`, `CC_APP_ENV=synthetic_dev` and `CC_CI_*_V1=1` feature flags; otherwise some APIs legitimately return 404/403.
3. Sign in to the existing password-protected demo account as patient/doctor; clinical-source actions still require valid links, invitation and consent. Open patient AI, the doctor's alert center, a patient's visit editor, both library URLs and questionnaire assignment. For Qwen, start Ollama and verify the local model specified by `CC_CI_NLP_MODEL` exists. When unavailable, the NLP extractor may use an explicitly labeled deterministic fallback; physician/patient chat itself requires local provider availability.
4. Read the failure text if API operations return 403/404/409/422: these may be access, consent, stale-version or missing-model conditions, not UI bugs. Do not disable guards to suppress them.
