# Интеграция терапии и лекарственного каталога

## ID, пути и навигация
- Diagnosis — `code` МКБ-10, например `F32`; обратные связи в `diagnosis.treatment_links.therapy_methods[]`, `medicines_active_substances[]`, `supplied_products[]`.
- Therapy — стабильный `id` (например `cbt`); обратные связи `diagnosis_links[]`; деталь `therapies/by_id/{id}.json`.
- Substance — стабильный `id` (например `sertraline`); обратные связи `diagnosis_links[]`; деталь `medicines/by_inn/{id}.json`.
- Branded product — отдельный `id` на конкретную форму и инструкцию; original `medicines/source_product_instructions/{basename}` and overlay `medicines/source_product_overlays/{id}.json`.

### Рекомендуемые маршруты UI
- `/doctor/clinical-library/diagnoses/:icd10` — «Методы лечения» и «Препараты (МНН)» с основанием связи и датой источника.
- `/doctor/clinical-library/therapies/:id` — «При каких диагнозах применяется».
- `/doctor/clinical-library/medicines/:inn` — «Возможная клиническая применимость» и «Инструкции доступных торговых препаратов».
- `/doctor/clinical-library/medicines/products/:id` — страница торгового продукта; обратная навигация «Диагнозы из этой инструкции».

Разграничить: 1) рекомендацию в иностранных клинических руководствах, 2) зарегистрированное российское показание конкретного продукта, 3) симптоматическое/внеинструкционное применение. Не показывать все эти связи одним бейджем «показано».

## Схема API (предложение, не реализовано)
`GET /api/v1/clinical-library/diagnoses/F32` (показать `treatment_links`),
`GET /api/v1/clinical-library/therapies/cbt`, `GET /api/v1/clinical-library/medicines/sertraline`,
`GET /api/v1/clinical-library/medicine-products/zoloft_sertraline_50mg`.
В back-end держать связь через join tables `clinical_therapy_indications`, `clinical_substance_indications`, `product_label_claims` с `evidence_source_id`,`review_status`,`age_population`,`clinical_context`,`country`,`label_status`,`valid_from`.

## Права и функции
- Гость или пациент: публичная просветительская версия после утверждения клиническим редактором и проверки прав; не показывать «список назначений».
- Врач: подробная клиническая версия; источники и ограничения явно видны.
- Админ: права редактировать метаданные только по роли; все правки версионировать, указывать автора/источник, делать двойное одобрение клинических связей.
- Отключить рекомендации препаратов, доз, диагнозов и терапии по ответу на опросник. В исходном каталоге таких функций нет.
- Санитизация текста, field-level ACL, API pagination/cache, индексы по code/id, лог аудита, запрет встраивать сторонние мануалы без лицензии.

## Предложение правил принятия
1. Проверить каждый исходник NICE/WHO/VA, а также текущие российские клинические рекомендации для важнейших нозологий.
2. По каждому МНН и *каждой лекарственной форме* проверить ГРЛС, существующую регистрацию, показания, противопоказания и редакцию ОХЛП; сохранять дату и источник.
3. Отдельно запретить замещающую терапию опиоидами/контролируемые стимуляторы до юридической экспертизы российского права.
4. Утвердить/отклонить клинические связи по степени доказательности и возрастным ограничениям; не выводить в прод любые данные со статусом `needs_specialist_review`.
5. E2E путь diagnosis↔therapy↔medicine↔product↔diagnosis; протестировать 403/404, отказ при неподтверждённых правах, нет дублирования МНН.
