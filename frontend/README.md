# Clinical Compass — frontend rebuild (Liquid Glass Clear)

Новая самостоятельная папка `frontend`, созданная с нуля по `Clinical_Compass_Frontend_Prompt_TZ(2).docx` с учётом фактических роутов `backend/cc_api`. **Никакой исходный backend, тесты backend и база данных не изменены.** Основной интерфейс написан на HTML/CSS/vanilla JavaScript без сборщика, React, CDN или внешних шрифтов. Файлы оригинального интерфейса не перенесены; исключение — 3 фото учебных специалистов, которыми может пользоваться публичный каталог.

## Установка в существующий проект

1. Сохраните резервную копию текущей папки `frontend` вашего проекта.
2. Распакуйте этот ZIP и замените папку `<корень проекта>/frontend` новой папкой `frontend` из архива целиком (не объединяйте старые CSS/JS с новыми).
3. Для запуска **существующего backend** используйте прежнее окружение проекта и задокументированный штатный запуск с корня проекта:

```bash
./scripts/evaluation.sh check --workspace "$HOME/Library/Application Support/ClinicalCompassEvaluation"
./scripts/evaluation.sh doctor --workspace "$HOME/Library/Application Support/ClinicalCompassEvaluation" --email expert@evaluation.test
./scripts/evaluation.sh serve --workspace "$HOME/Library/Application Support/ClinicalCompassEvaluation" --port 8766
```

Откройте `http://127.0.0.1:8766/`. Создавайте синтетические тестовые аккаунты только если конфигурация сервера позволяет. `doctor` может запросить ввод собственного пароля; предзаполненных паролей в пакете нет. Для штатного окружения автор проекта ранее указал macOS Apple Silicon, Python 3.11, Conda `cc-m1`; эти настройки **не были повторно проверены на данной машине**. Новый frontend не требует `npm install`/`npm build`.

> При запуске через Flask маршруты `/` и `/<path>` отдают `frontend/dist/index.html`, а статические файлы обслуживаются из `frontend/dist`. Старые ссылки вида `/#/doctor/...` поддержаны. Прямые URL `/doctor/...` попадают в SPA через Flask fallback. `/api/v1/*` никогда не обрабатываются как HTML.

## Главные проектные решения

- Liquid Glass **Clear** — материал по умолчанию. Не предусмотрены Matte, Optical и переключатель режимов стекла. Шапка и меню находятся в **разных backdrop-root**, потому оба размываются независимо. Модальные окна рендерятся в отдельном корневом слое, затемняют/размывают всё приложение и возвращают фокус при закрытии. Предусмотрена непрозрачная подложка при отсутствии `backdrop-filter`.
- Светлая и тёмная темы оформлены общими CSS-токенами; переключатель расположен **только в модальном окне настроек**. Выбор запоминается браузером в `localStorage` (`cc.theme`) и не передаётся на сервер.
- Весь динамический текст API экранируется, клинические данные не выдумываются. Отрисовка защищённых разделов зависит от реального `auth/me`, но **сервер** остаётся единственным арбитром прав. Вход, выход и мутации происходят только через реальные API, подтверждённые ответы, CSRF и cookies same-origin.
- Доступны отдельные состояния loading, empty, error, forbidden; в формах запрещена повторная отправка; при ошибке изменений нет ложного уведомления об успехе. Обрабатываются HTTP 401/403/404/409/422/429/5xx. Успешные действия обновляют данные с сервера.
- Основные прикладные сценарии: публичный каталог и профиль, локальный синтетический вход/регистрация, приглашение/согласие, кабинет пациента, check-in, технические опросники, дневник выполнения, обращения и первый чат, предложения и подтверждения приёма, уведомления, профиль/фото, кабинет врача, доступные сигналы/карты, профессиональный чат, синтетическая NLP-лаборатория, read-only разделы клиники и исследователя.

## Границы реализации

**Это замена frontend с частичной интеграцией, а не подтверждённый полный клинический продукт.** Файлы `INTEGRATION_MATRIX.csv` и `TEST_REPORT.md` содержат разбивку на `чтение`, `запись`, `частично`, `недоступно`, `локально`, `переход`. Для некоторых плановых страниц нет подтверждённого способа безопасного действия или не реализована полная серверная схема; на них отображается аккуратное состояние недоступности, а не имитация сохранения.

В частности: пользовательский чат-помощник и клинический Copilot без связанного с ACL контекста, аудио/видеокомнаты, верифицированные отзывы, конструктор когорт, некоторые клинические изменения, мастер оценочных D01–D10, точная авторизация организационных приглашений и мастер подписания документов в этом фронтенде **не завершены**. При этом в backend может присутствовать часть соответствующих маршрутов: это не значит, что frontend подключил все их операции. Привязка к реальному Qwen/Ollama, PostgreSQL, Keycloak/MFA, почтовым сервисам и видеосвязи не проверялась.

## Проверка без сторонних npm-зависимостей

```bash
cd frontend
npm test
```

Выполняются проверки 95 маршрутов и 25 репрезентативных состояний с тестовыми API-ответами. Эти тесты **не заменяют** автоматизацию в браузере и работу на реальном Flask. Проверки backend и Selenium/Playwright из исходного проекта не запускались из-за отсутствия Python `flask` и политики запуска Chromium в текущем контейнере; см. `TEST_REPORT.md`.

Окончательная интеграция у пользователя требует проверки: реальных (синтетических) пользовательских сессий каждой роли, ошибок API, приватности, клавиатурной навигации, макетов при 360/768/1280px, Safari Liquid Glass, OIDC, и работы полной цепочки «анкета → первое сообщение → ответ врача → предложение времени → подтверждение».

## Обновление оформления: Warm Frost / Graphite (27.10.2026)

- Светлая тема теперь использует чисто-белый фон (`--bg: #ffffff`), оранжевые акценты и графитовые основные кнопки. Тёмная тема оставлена работоспособной в графитово-янтарных цветах.
- Все материалы стекла подключены к общим токенам `--glass-fill`, `--glass-fill-raised`, `--glass-rim`, `--glass-top-glow`, `--frost` и `--frost-dense`. Центральная часть материала полупрозрачная; верхняя кромка ярче боковых.
- Полный радиус у кнопок и вкладок регулируется одним `--r-pill`, вложенные поверхности используют `--nested-radius` (меньше `--r-xl` внешних карточек).
- Применено к header, отдельному floating dropdown, sidebar, карточкам, диалогам, toast, полям и состояниям; технический экран API Lab наследует тот же CSS.
- На главной информационной карточке появился графитовый стиль `graphite-feature`. Её тексты и маршруты не менялись.
- Добавлен статический регрессионный тест `tests/design.mjs`, запускается через `npm test` вместе со smoke-тестом.
- Бэкенд, сетевые контракты и логика JS не изменены; правка `views.js` касается **только** CSS-класса одной карточки.

> На чисто белом фоне физический эффект `backdrop-filter` заметнее всего при прокрутке контента за шапкой или при открытии модального окна. Полупрозрачность и контур читаются на белом благодаря тёплому тонированию и слабым теням. Safari рекомендован для окончательной ручной проверки blur и производительности.
