## 2. Non-negotiable demo outcomes

**The release must have verified working journeys**, with working navigation, real API actions and durable state, for:

2. **Doctor:** account login, synthetic patient linking/invitation and consent, patient chart/intake, appointment drafts and saving, questionnaires assign/review, safety signals, clinical catalog, Clinical Intelligence NLP evidence and tags, proposed chart text, physician edits/confirmation, referrals, treatment references and clinical copilot. **Reachability:** no unexplained 404/422/500, dead button, unhandled route, broken modal/back path, scroll jump, missing disabled reason or false “saved” notice along juror journeys. - Experimental Clinical Intelligence and Qwen are welcome in a **synthetic** jury demo. Show **what works** (tags, evidence, draft chart suggestions, routing suggestions, manual review, catalog navigation), while marking the algorithm `experimental_needs_validation` and showing source/evidence. Do not represent model suggestions as an established diagnosis, prescribed drug, treatment decision, a medical approval or 24/7 monitoring.

Preserve role-/organization-/source-ACL, consent, CSRF, idempotency, audit, concurrency/version checks and patient-private diary isolation. Synthetic demonstration must never bypass these gates.

Keep instrument rights and clinical release checks for real deployments. Unavailable/licensed forms remain legitimately view-only.

## 5. Docker design guardrails (Phase 3)

- The present `LocalOllamaProvider` permits loopback (`127.0.0.1`) only; this **will not automatically reach Ollama on the Mac host from inside Docker**. Demonstrate a safe real connection, e.g. an Ollama sidecar with an explicitly designed network namespace, or a deliberately reviewed restricted host connection. Do not silently change hostname allowlists, disable redirect/proxy restrictions, open Ollama on all host interfaces, or swap in a cloud/mock provider.
- On macOS, Ollama in a Linux Docker container may not have direct Apple Metal acceleration and could be substantially slower. Preserve a proven **native Mac + host Ollama** launch option alongside the Docker demo; clearly distinguish benchmark results for these modes. No embedded Qwen weights in the shipped source archive; pin/document tag/digest and a separate volume/pull procedure.
- Publish the app on `127.0.0.1` only by default; no exposed DB/Ollama services to public networks. Container user non-root if practicable, explicit volumes, stable secrets with strict permissions, reproducible dependency lock, no baked credentials/PII, limited resource configuration and startup/readiness checks. If existing Flask launcher binds only loopback *inside* container, implement and test a safe WSGI bind to container interface while host publication remains localhost-only.
- On fresh `docker compose up`, verify initialization/migrations without destroying persisted state, Qwen response, all four scored forms and profile saves, clinic FIO consent, catalog completeness, researcher and doctor flows; `down`/`up` must retain state, and fresh-volume reset must be explicit, not automatic.
